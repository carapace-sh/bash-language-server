# AGENTS.md

Guidance for AI agents working in this repository.

## What this project is

This is the **carapace-sh fork of bash-lsp/bash-language-server**: a TypeScript
implementation of a Bash Language Server (stdio LSP), modified to add command
completions backed by [carapace](https://github.com/carapace-sh/carapace-bin).
The fork is an experimental proof-of-concept: the vscode client extension was
removed, eslint/prettier/tsc configs were removed, and the build was switched
from tsc to `bun build`. Only the language server remains (`server/src/cli.ts start`).

Because it is a fork, much of the code (analyser, server, shellcheck, shfmt
integration) comes from upstream; the fork-specific surface area is small and
concentrated in `server/src/carapace.ts`, the carapace wiring in
`server/src/server.ts` (`updateConfiguration`, `onCompletion`), quote-stripping
in `server/src/analyser.ts` (`commandContextAtPoint`), and the `carapacePath`
config option in `server/src/config.ts`.

## Commands

- `bun install` — install dependencies (bun.lock is authoritative; there is no
  package-lock.json).
- `bun test --isolate` — run all tests. **This is the canonical runner.**
- `bun test --isolate <path>` — run a single suite, e.g.
  `bun test --isolate server/src/__tests__/carapace.test.ts`.
- `bun test --isolate --coverage` — tests with coverage.

Bun is not necessarily installed on every dev machine; `npx jest` works after
`npm install`, but see the gotchas below before relying on it.

### Test prerequisites

- `shellcheck` and `shfmt` must be on PATH for the shellcheck and shfmt test
  suites (CI installs them via apt-get). Without them those suites fail, which
  is an environment problem, not a code problem.
- `carapace` is **not** needed for tests; `CarapaceProvider` tests use either
  an empty/nonexistent path or only exercise `toCompletionItems` (no spawn).
- `server.test.ts` and `shellcheck/index.test.ts` use snapshots
  (`__snapshots__` next to the tests).

## Gotchas

- **`tsconfig.json` exists for ts-jest only.** The fork switched the build
  from tsc to `bun build`, so bun does not need it, but the jest config in
  `package.json` is still active. ts-jest requires `esModuleInterop: true`
  to compile suites that import modules using `export =` (`web-tree-sitter`,
  `turndown`), so the root `tsconfig.json` sets it. Don't remove it.
- **`tiny-editorconfig` is a runtime dependency** (imported by
  `server/src/shfmt/index.ts`). It was previously a devDependency that only
  worked because `bun build --compile` bundles devDependencies; it has been
  moved to `dependencies`. A `__mocks__/tiny-editorconfig.js` jest mock still
  exists for tests.
- **tree-sitter WASMs are embedded as base64 TypeScript files**
  (`server/src/tree-sitter.ts`, `server/src/tree-sitter-bash.ts`), generated by
  `server/scripts/encode-wasm.sh` from
  `node_modules/web-tree-sitter/tree-sitter.wasm` and
  `server/tree-sitter-bash.wasm`. Never hand-edit the `.ts` files; regenerate
  them. The wasm upgrade is automated by
  `.github/workflows/upgrade-tree-sitter.yml` (which, oddly, uses pnpm for the
  checkout step and bun inside `server/`); `server/parser.info` records the
  tree-sitter-bash commit/CLI version the wasm was built from.
- **Release builds are goreleaser-driven** (`.goreleaser.yaml`): bun compiles
  `server/src/cli.ts` into a single binary per platform, injecting the version
  via `--define BUILD_VERSION="..."`. `BUILD_VERSION` is a compile-time global
  declared in `cli.ts`; it does not come from package.json (whose version is
  just `0.0.0`).
- **The logger emits LSP notifications, not stdout** (`util/logger.ts`).
  Logging before `setLogConnection` runs drops messages. Log level comes from
  the `BASH_IDE_LOG_LEVEL` env var or the `logLevel` config key.
- **Configuration is validated with zod** (`ConfigSchema` in
  `server/src/config.ts`). Any new setting must be added there plus to
  `getConfigFromEnvironmentVariables()` if it should be env-var configurable;
  env-var config is deprecated in favor of the `bashIde` LSP configuration
  section, but still supported.
- **The server tests globally mock `setTimeout`** to skip the shellcheck
  debounce (`server/src/__tests__/server.test.ts`). `CarapaceProvider` captures
  the real `setTimeout`/`clearTimeout` at module load so its spawn timeout is
  not short-circuited by this spy; keep using those captured references if you
  add timer-based logic in `carapace.ts`.
- **`commandContextAtPoint` returns only *complete* arguments before the
  cursor.** The partial word being typed is appended by the caller (the server
  appends the LSP `word`, or `''` at a word boundary) so carapace receives the
  exact text for the position being completed. The cursor column passed in is
  already `position.character - 1`; do not re-apply partial extraction inside
  `commandContextAtPoint`.

## Architecture

Flow: `cli.ts` creates a stdio LSP connection → `BashServer.initialize`
(`server/src/server.ts`) builds the components → `server.register(connection)`
wires all LSP handlers. `BashServer` is the glue; the interesting pieces:

- **Analyzer** (`analyser.ts`, ~1200 lines): parses documents with tree-sitter,
  tracks symbols across the workspace (background analysis limited by
  `backgroundAnalysisMaxFiles`, glob `**/*@(.sh|.inc|.bash|.command)`), and
  provides `commandContextAtPoint` used by completion. For the carapace fork it
  also strips leading/trailing quotes from command arguments before they are
  passed to carapace (the shell-level quoting is re-applied later at insert
  time).
- **CarapaceProvider** (`carapace.ts`): spawns
  `carapace <command> export <command> <args...>` with a 5s timeout and parses
  the JSON export (`{ version, values: [{value, display, description, tag}],
  nospace }`). It self-disables after 3 consecutive spawn errors (a non-zero
  exit *without* spawn error does not count toward the limit). Completion items
  use `display` as label and `value` as `filterText`/inserted text; values
  containing spaces/special chars are single-quoted via `quoteShellValue`;
  tags like "longhand flags"/"directories" map to LSP CompletionItemKinds.
- **Completion precedence** in `server.ts#onCompletion`: if the cursor is
  inside a command and carapace is enabled, carapace results replace *all*
  general completions (reserved words, workspace symbols, PATH executables,
  builtins, snippets are skipped). If carapace returns nothing, the fallback is
  upstream behavior: flag options via the embedded `get-options.sh` script
  (bash-completion's `_command_offset`) when the word starts with `-`, plus the
  general completions.
- **Linter** (`shellcheck/`): spawns shellcheck with JSON output, debounced
  500ms per document; extracted `codeActions` are cached per-URI for quick-fix.
  `shellcheckExternalSources` (default true) controls `--external-sources`.
- **Formatter** (`shfmt/`): spawns shfmt, honoring .editorconfig unless
  `shfmt.ignoreEditorconfig`.
- **Executables** (`executables.ts`): snapshot of PATH used to suggest
  executables in completion and validate commands.
- Config plumbing: on `initialized`, config is read from the client
  (`bashIde` section) or env vars; `updateConfiguration` instantiates/disables
  the linter, formatter, and carapace provider based on whether their
  executable paths are non-empty (empty string disables the feature).

## Testing patterns

- Tests live in `__tests__` directories next to the code; the jest/bun
  `testMatch` glob is `**/__tests__/*.ts`. Helpers live in `testing/`:
  `fixtures.ts` (a `FIXTURE_URI`/`FIXTURE_DOCUMENT` map over
  `testing/fixtures/*.sh`), `mocks.ts` (`getMockConnection()`), and
  `testing/executables` (fixtures with/without the executable bit).
- Server-level tests initialize the real `BashServer` against the fixtures
  folder with a mocked connection, invoke handler callbacks directly from
  `connection.<handler>.mock.calls`, and assert on LSP responses. Global
  `setTimeout` is mocked to skip the ShellCheck throttle delay; the Logger is
  silenced via `jest.spyOn(Logger.prototype, 'log')`.
- Snapshot tests exist for analyzer diagnostics and shellcheck results; URIs
  inside snapshots are workspace-absolute, and `updateSnapshotUris` in
  `testing/fixtures.ts` normalizes them for assertions.

## Style

- TypeScript, 2-space indent, single quotes, mostly no semicolons.
- There is intentionally **no** linter, formatter, or tsconfig; don't re-add
  them as a drive-by.
- Error handling for external binaries follows a consistent pattern: log via
  `logger.warn`/`logger.debug`, degrade gracefully (return empty results,
  disable the feature), never crash the server on a missing binary.

## External binaries

| Tool | Used for | Missing means |
| --- | --- | --- |
| `shellcheck` | diagnostics/quick fixes | linting disabled (`shellcheckPath: ""`) |
| `shfmt` | formatting | formatting disabled (`shfmt.path: ""`) |
| `carapace` | command completions | carapace completions disabled (`carapacePath: ""`), upstream fallback used |
| `bash` + bash-completion | `get-options.sh` fallback for flag completion | fewer flag completions |
